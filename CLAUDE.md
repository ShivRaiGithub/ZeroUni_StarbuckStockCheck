1. Every service's API contract is a fixed OpenAPI spec.
2. No shared database. Each service owns its own data.
3. No merge until the contract tests pass.
4. `store_closed`: if the order's store is closed, the order MUST be refused with HTTP 409, error code `store_closed`, and message "<Store Name> is closed right now and can't take mobile orders." (e.g. "Bellevue Square is closed right now and can't take mobile orders.").
5. `base_out_of_stock`: if a line item's base component (milk) has available stock <= 0 (`quantity_on_hand - reserved_quantity`), the order MUST be refused with HTTP 409, error code `component_unavailable`, `missing_component` set to the milk, and message "Line <n>, <Size> <Drink>: <Component> is unavailable at this store right now."
6. `add_in_out_of_stock`: if any add-in on a line item has available stock <= 0, the order MUST be refused with HTTP 409, error code `component_unavailable`, `missing_component` set to the add-in, and the same message format as rule 5. A partial order MUST never be accepted by dropping the add-in.
7. `stock_runs_out_mid_order`: if a component is in stock when the order starts but runs out before the order is fulfilled, the order MUST be refused with HTTP 409, error code `component_unavailable`, `missing_component` set to the component that ran out, and the same message format as rule 5. Stock MUST be re-checked at commit time, and the order MUST never be accepted from a stale earlier check.
8. `insufficient_quantity`: if the available stock of a component is positive but less than the quantity the order needs (line `quantity` times units per drink), the order MUST be refused with HTTP 409, error code `component_unavailable`, `missing_component` set to the short component, and the same message format as rule 5. Stock MUST never go negative.
